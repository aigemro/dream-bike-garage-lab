# 디자인·사운드 표현 실험 규칙

이 문서는 Dream Bike Garage Lab에서 디자인, 애니메이션, 이펙트, 사운드 방안을 비교할 때 적용하는 규칙입니다.

전체 에셋의 최종 관리 기준은 메인 저장소의 [디자인·사운드 에셋 운영 규칙](https://github.com/aigemro/dream-bike-garage/blob/main/docs/development/ASSET_WORKFLOW.md)을 따릅니다.

## 실험 대상

- 머지 성공 애니메이션과 효과음
- 자전거 조립 연출과 조립음
- 주문 완료 화면과 보상 피드백
- UI 스타일과 상호작용 피드백
- 배경음 및 상황별 사운드 전환

## 운영 원칙

1. 한 가지 방안을 바로 확정하지 않고 Prototype A/B/C 등 비교 가능한 안으로 만듭니다.
2. 같은 트랙은 동일한 게임 상태, 화면 크기, 음량과 조작 조건에서 비교합니다.
3. 각 프로토타입은 사용한 임시 에셋의 출처와 라이선스를 기록합니다.
4. 평가 결과는 `채택 / 조건부 채택 / 보류 / 폐기` 중 하나로 남깁니다.
5. 채택된 결과는 메인 저장소 Issue로 연결합니다.
6. Lab의 임시·비교용 에셋은 최종 게임 에셋으로 간주하지 않습니다.
7. 최종 export 파일과 게임 적용 코드는 메인 저장소의 구조와 성능 기준에 맞춰 다시 정리합니다.

## 공통 평가 기준

| 항목 | 확인 내용 |
|---|---|
| 콘셉트 적합성 | 자전거샵 아르바이트와 캐주얼 머지 경험에 어울리는가? |
| 인지성 | 행동의 성공·실패와 다음 목표가 즉시 전달되는가? |
| 조작 피드백 | 터치와 마우스 입력에 자연스럽게 반응하는가? |
| 쾌감 | 머지, 조립, 보상 순간이 충분히 만족스러운가? |
| 피로도 | 반복 재생 시 시각·청각적으로 과하지 않은가? |
| 성능 | 모바일 브라우저와 WebView에서 끊김이나 지연이 없는가? |
| 확장성 | 새 부품·자전거·이벤트에도 재사용할 수 있는가? |
| 제작 비용 | 최종 품질로 발전시키는 비용이 적절한가? |

## 결과 기록에 포함할 내용

- 실험 질문과 가설
- Prototype별 차이
- 사용 에셋의 출처와 라이선스
- 테스트 환경과 조작 방법
- 스크린샷 또는 짧은 플레이 기록
- 공통 기준 비교 결과
- 결론과 선택 이유
- 메인 저장소 반영 Issue
