# 진행 상태 저장 비교 실험

> 관련 이슈: [#3 게임 저장 방식 비교 실험](https://github.com/aigemro/dream-bike-garage-lab/issues/3)<br>
> 범위: 서버가 필요 없는 브라우저 로컬 저장 A/B안 구현 및 비교

## 목적

보드 부품, 보유 재화, 현재 주문을 브라우저 종료·새로고침 뒤에도 복구할 수 있는지 같은 조건으로 검증합니다. 이번 단계에서는 제품 저장 정책을 확정하지 않고, 웹 MVP에 사용할 로컬 저장 후보의 차이를 확인합니다.

## 공통 저장 데이터

- `schemaVersion`: 저장 구조가 변경될 때 마이그레이션 기준
- `revision`: 저장 횟수와 로컬·서버 충돌 비교 기준
- `savedAt`: 마지막 저장 시각
- 보유 코인, 진행 중인 주문 번호, 보드 부품 목록

두 방안은 동일한 상태 변경 버튼과 초기 데이터를 사용합니다. 저장소 구현만 교체할 수 있도록 `SaveRepository` 인터페이스로 분리했습니다.

## 비교 방안

| 항목 | A안 localStorage | B안 IndexedDB |
|---|---|---|
| 서버 | 불필요 | 불필요 |
| 처리 방식 | 동기식 문자열 저장 | 비동기 트랜잭션 저장 |
| 데이터 형태 | JSON 직렬화 | 구조화 객체 |
| 실험 슬롯 | 단일 슬롯 | 3개 슬롯 |
| 적합한 범위 | 작은 MVP 상태, 설정값 | 보드·수집·여러 슬롯 등 확장 상태 |
| 주요 한계 | 용량과 동기 처리, 문자열 변환 | 구현 복잡도와 비동기 오류 처리 |

## 동일 검증 절차

1. 코인, 부품, 주문 상태를 변경합니다.
2. 현재 상태를 저장합니다.
3. 새로고침하거나 상세 화면에서 나갔다가 다시 진입합니다.
4. 저장 상태를 불러옵니다.
5. 코인·주문·부품·revision이 저장 시점과 같은지 확인합니다.
6. B안은 슬롯마다 다른 상태를 저장해 서로 분리되는지 추가 확인합니다.
7. 저장 삭제 뒤 불러왔을 때 데이터 없음 안내가 표시되는지 확인합니다.

## 복원·오류 처리 기준

- A/B 모두 화면 진입 시 현재 저장 위치를 자동으로 불러옵니다.
- B안은 저장 슬롯을 바꾸는 즉시 해당 슬롯을 불러오며, 비어 있으면 새 진행 상태를 표시합니다.
- 저장 데이터는 `schemaVersion`, 진행 수치, 부품 구조를 확인한 뒤에만 적용합니다.
- 지원하지 않거나 손상된 데이터는 현재 진행에 덮어쓰지 않고 초기 상태와 오류 안내를 표시합니다.
- 저장 삭제 시 화면 상태도 초기화해 삭제한 데이터가 남아 있는 것처럼 보이지 않게 합니다.

## 서버 저장이 필요한 조건

이번 A/B 구현에는 서버가 필요하지 않습니다. 다음 요구가 확정되면 후속 C안으로 서버 동기화를 별도 실험합니다.

- 토스 로그인 사용자와 저장 데이터 연결
- 기기 변경 후 이어하기와 앱 삭제 후 복구
- 결제 보상, 중요 재화, 랭킹처럼 클라이언트만 신뢰할 수 없는 데이터
- 운영자 복구와 변경 이력
- 여러 기기에서 발생한 저장 충돌 처리

후속 후보는 IndexedDB에 먼저 저장하고 서버에 비동기로 동기화하는 하이브리드 방식입니다. `revision`, `savedAt`, 사용자 식별, 충돌 정책이 필요하며 인증 방식이 정해진 뒤 API와 DB를 준비합니다.

## 1차 평가 방향

- A안은 구현이 가장 단순하므로 작은 웹 MVP 기준선으로 평가합니다.
- B안은 비동기 저장과 슬롯 분리를 제공하므로 실제 게임 확장 후보로 평가합니다.
- 최종 채택은 앱인토스 WebView의 데이터 유지 조건과 로그인 정책을 확인한 뒤 메인 저장소에서 결정합니다.

## C안 · 통합 상태 자동 저장·복구 (#5 결합)

> 관련 이슈: [#5 앱 라이프사이클 및 상태 복구 검증](https://github.com/aigemro/dream-bike-garage-lab/issues/5) · 상위: [#113 출시 MVP 통합 검증](https://github.com/aigemro/dream-bike-garage-lab/issues/113)

A/B 비교에서 정리한 저장 계약을 출시 MVP의 통합 상태(보드, 현재 주문, 코인, 성장 단계, 튜토리얼)에 적용하고, 저장 버튼 없이 라이프사이클 이벤트에서 자동 저장합니다.

- 자동 저장 시점: `visibilitychange`(hidden)로 백그라운드 전환을, `pagehide`로 새로고침·탭 닫기·페이지 이동을 처리합니다. iOS WebView에서 `beforeunload`가 불안정하므로 사용하지 않습니다.
- 복원 규칙: 진입 시 자동 복원하며, 마지막 저장의 revision과 저장 사유(수동/백그라운드/페이지 이탈)를 표시해 어느 시점으로 돌아왔는지 확인할 수 있습니다.
- 손상 데이터: 스키마 검증에 실패하면 진행에 적용하지 않고 첫 실행 상태와 오류 안내를 표시합니다.
- 남은 검증: 앱인토스 WebView 실기기에서 백그라운드 전환·강제 종료 후 복구 조건 판정은 #4·#117과 함께 진행합니다.

자세한 절차는 [variants/storage-integrated-auto.md](variants/storage-integrated-auto.md)를 참고하세요.
