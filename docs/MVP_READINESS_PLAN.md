# 출시 MVP 통합 검증 계획

> 기준일: 2026-08-14  
> 상위 트랙: [#113 출시 MVP 통합 검증](https://github.com/aigemro/dream-bike-garage-lab/issues/113)

## 1. 결론

현재 Lab에는 머지, 부품 수급, 주문·조립, 보상·성장, 수집, 홈 화면, 입력, 반응형, 저장 후보가 개별 실험으로 준비되어 있습니다. 다음 목표는 새 기능을 넓히는 것이 아니라 이 결과를 **하나의 작은 출시 흐름으로 연결하고 복구·모바일·첫 플레이 품질을 검증하는 것**입니다.

출시 MVP의 핵심은 다음 한 문장으로 제한합니다.

> 고객 주문을 받아 부품을 수급하고 2-to-1로 머지해 자전거를 조립·납품한 뒤, 받은 급여로 내 드림 바이크를 성장시키고 다음 주문을 이어서 플레이한다.

## 2. 현재 상태와 MVP 차이

| 영역 | 현재 Lab 상태 | 출시 MVP까지 필요한 작업 | 연결 |
|---|---|---|---|
| 머지·수급 | A/B/C 체험 가능 또는 검토 준비 | 채택 후보를 공통 상태 모델로 연결 | #9, #70 |
| 주문·조립 | 자동/직접 장착 비교 가능 | 주문 3종 연속 및 단계별 완성 연결 | #16, #114 |
| 보상·성장 | 고정/성과/타이머 비교 가능 | 코인과 내 자전거 3단계 성장 연결 | #19, #116 |
| Collection·홈 | 도감/Garage와 홈 D/E 비교 가능 | 대표 자전거 성장 결과를 홈에 반영 | #11, #87 |
| 저장·복구 | 방식 및 라이프사이클 이슈 존재 | 보드·주문·코인·성장 통합 저장 계약 | #3, #5 |
| 입력·화면 | A/B/C 비교 구현 진행 | 모바일 세로·Safe Area 실기기 판정 | #4, #33 |
| 첫 플레이 | 레벨·해금 초안 존재 | 첫 주문 튜토리얼과 막힘 구제 | #106, #115 |
| 출시 품질 | 운영·앱인토스 기반 이슈 존재 | 권리·에셋·QA·오류·복귀 체크 | #6, #7, #117 |

## 3. 권장 최소 콘텐츠

- 가상 자전거 주문 3종: 로드, MTB, 그래블
- 부품 3~4종: 프레임, 휠셋, 구동계, 핸들바 후보
- 한 번에 주문 1건
- 동일 종류·동일 레벨 2-to-1 머지
- 내 드림 바이크 최소 3단계 성장
- 초기 주문 3종 이후 반복 주문 생성
- 로컬 저장: 보드, 현재 주문, 코인, 성장, 튜토리얼 상태
- 앱인토스 세로 화면 우선, 웹 빌드는 검토·공유용 유지

## 4. 실행 순서

1. **수직 슬라이스 계약 정의** — 화면 전환, 상태 데이터, 기존 트랙 연결 경계를 #114에서 확정합니다.
2. **첫 주문 완주 보장** — #115에서 안내와 진행 불가 구제를 비교합니다.
3. **반복과 성장 데이터** — #116에서 주문 3종, 반복 규칙, 3단계 성장 비용을 검증합니다.
4. **저장·복구 결합** — #3·#5 결과를 통합 상태에 적용해 새로고침·복귀·재실행을 확인합니다.
5. **모바일·출시 판정** — #117에서 #4·#6·#7 결과와 에셋 권리·QA 증거를 묶습니다.
6. **메인 이관** — Lab은 채택 후보·한계·측정 결과를 기록하고 메인 저장소에서 출시 코드를 구현합니다.

## 5. 출시 판정 기준

- 주문 3종을 처음부터 끝까지 연속 완료할 수 있다.
- 첫 사용자가 주문 목표, 머지 방법, 급여 사용처를 설명할 수 있다.
- 드림 바이크를 최소 한 단계 성장시키고 다음 목표를 확인할 수 있다.
- 첫 3종 이후에도 다음 주문이 생성된다.
- 새로고침·앱 복귀 후 보드·주문·코인·성장이 복구된다.
- 390×810 모바일 화면에서 겹침·잘림 없이 핵심 조작이 가능하다.
- 진행 불가 오류가 없고 잘못된 입력에 피드백과 복구 수단이 있다.
- 실제 브랜드나 권리 불명 에셋이 남아 있지 않다.
- 앱인토스 심사에 필요한 기본 설명·아이콘·대표 이미지 후보가 준비된다.

## 6. MVP 이후로 미루는 범위

실제 글로벌 브랜드, 매치3, 레이스, 세계·한국 코스, 복잡한 샵 경영, 서버 계정·다기기 동기화, 광고·결제, 시즌 패스, 에너지 과금, 대리점 QR·O2O는 핵심 루프와 재방문 의도가 검증된 뒤 별도 트랙으로 진행합니다.
