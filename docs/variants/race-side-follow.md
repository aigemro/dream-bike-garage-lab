# A안 · 사이드뷰 카메라 추적 레이스

## 검증 가설

급여로 참가비를 내고 보유 자전거로 출전하는 자동 관람형 대회는, 내 자전거가 실제로 달리는 모습을 따라가며 보여줄 때 성장 보상의 체감이 가장 크다. 오르막·내리막 구간의 순위 변동이 화면에서 읽히면 결과 발표까지의 관람 시간이 지루하지 않다.

## 이번 구현

- 순수 로직 모듈 `race-progress.ts`: 대회 일정(5일차마다 개최)·참가비(500)·시드 기반 시뮬레이션·보상 정산을 Phaser 없이 분리, Vitest 단위 테스트 포함
- 결과 선확정·재생 분리: 시뮬레이션이 틱별 진행 타임라인을 먼저 확정하고, 씬은 타임라인을 보간 재생만 담당
- 리버사이드 서킷 1,200m 4구간: 스타트 직선 → 오르막(감속 0.72배) → 내리막(가속 1.3배) → 피니시 스퍼트(1.1배)
- 속도 점수 = 17 + 성능 레벨 × 2.5 + 드림 단계 × 1.5 (21~31.5), NPC 7명은 20.5~29.5 고정 밴드
- 참가 화면에서 성장 프리셋(갓 완성/성장 중/드림 완성)을 바꿔 등수 체감을 즉시 비교
- 사이드뷰 관람: 카메라가 내 자전거를 따라가고, 하늘·언덕 2겹 패럴랙스와 노면 대시가 스크롤
- 자전거 8대는 텍스처 캐시 경로(addPixelBikeImage)로 렌더링, 라이더는 픽셀 캐릭터 + 바운스 트윈
- Day HUD 문법 재사용: DAY 배지·대회명 골드 패널·미니맵 진행 바(darkWood + green)와 참가자 8명 점 표시
- 구간 진입 배너, 선두와의 간격(m), 배속 x1/x2 토글, 결승선 통과 슬로모션
- 정산: 등수 배너·입상자 기록·상금(1위 2,000 / 2위 1,200 / 3위 800 / 완주 200) 코인 카운트업, 입상 시 픽셀 색종이

## 체험 순서

1. 성장 프리셋을 고르고 참가비 500코인을 내고 출전한다.
2. 카운트다운 후 자동 주행을 관람하며 오르막에서 순위가 흔들리는지 확인한다.
3. 배속 x2로 전환해 관람 시간이 적당한지 확인한다.
4. 완주 후 등수·기록·상금을 정산하고, 프리셋을 바꿔 한 번 더 출전해 등수 차이를 비교한다.

## 비교 기준

- A안(본 방안): 내 자전거 몰입감과 주행 연출 — 대신 전체 순위 파악은 미니맵에 의존
- B안: 8레인 전광판 중계 — 전체 순위 변동이 한눈에 보이지만 내 자전거 몰입은 약함

## 프로토타입 경계

참가비·상금·속도 계수는 Lab 체감 검증용 1차 수치이며 밸런스 확정은 메인 저장소 담당이다. Day 통합(대회 개최일 표시, day-account 화면 유니온 연결)과 저장 연동은 채택안 결정 후 후속 이슈로 진행한다.
