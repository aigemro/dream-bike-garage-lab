# 보상형 광고 SDK 연결 실험 (#275)

메인: aigemro/dream-bike-garage#92. 기존 체력 소진 #263 A/B/C에서 동일한 +10 충전 규칙으로 가짜 광고와 공식 SDK를 비교한다. 밸런스 확정이나 출시 코드는 아니다.

## 실행

- 기본: `#/track/energy-refill/refill-card/demo` (A), `refill-daily` (B), `refill-rest` (C).
- 토스 테스트 광고: 주소의 해시 **앞**에 `?rewardedAd=toss-test` 추가.
- 예: `https://aigemro.github.io/dream-bike-garage-lab/?rewardedAd=toss-test#/track/energy-refill/refill-card/demo`
- 로그인 → 프로필 → Day 시작 → Lab 체력 0 → 상자 → 광고 충전.
- 토스 모드는 공식 테스트 ID `ait-ad-test-rewarded-id`만 사용한다. 운영 광고는 호출하지 않는다.
- 브라우저에서는 SDK 미지원 실패를 안내한다. 토스 호스트에 탑재한 테스트 번들에서 실제 광고 검증이 필요하다. Pages 링크만 토스에서 열어서는 호스트 SDK 검증이 되지 않는다.

## 구현

SDK는 선택 시 동적 로드한다. 지원 확인 → 로드(15초 제한) → 표시 → reward 확인 → 닫힘 후 완료. 노출/클릭/닫힘만으로 지급하지 않는다. 중복 콜백·동시 요청을 막고 다음 요청마다 재로드한다. 광고 중 영업 시간을 정지하고 입력·오디오를 막는다. 기존 가짜 광고에도 같은 일시정지 처리를 적용한다.

## 검증과 한계

자동 테스트: 보상 이벤트, 중복, 클릭만 발생, 중도 종료, 로드 지연, 오류, 동시 요청, 재로드. 전체 테스트와 빌드 실행 결과는 PR에 기록한다.

실기기 확인 전: Android/iOS 광고 닫힘/복귀, reward와 dismissed 이벤트 순서, 화면 전환·앱 종료, 저장 실패. 표시 단계에는 임의 타임아웃 보상을 두지 않는다. 콜백이 오지 않는 호스트 문제는 실기기 검증 대상이다.

기존 Lab은 체력과 충전 기록을 별도 localStorage 키로 저장하므로 두 저장 사이 강제 종료의 원자성, 서버 시간·변조 방지, 종료 중 보상 복구를 보장하지 않는다. 이 PR은 운영 준비 완료를 의미하지 않는다. 실기기 결과 후 조건부 채택 여부를 메인 #92에 보고한다.
