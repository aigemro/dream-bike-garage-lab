# 머지 코어 D안 · 입고 상자 · 겹치기 머지

- 실험 ID: game-core / merge / prototype-d / v2
- 상태: 검토 준비 (독립 데모), 채택 여부: 미결정
- 개선 이슈: [#245](https://github.com/aigemro/dream-bike-garage-lab/issues/245)
- 최초 이슈: [#243](https://github.com/aigemro/dream-bike-garage-lab/issues/243)

## 질문과 가설
자전거 가게 알바가 입고 재고를 정리하고 고객 자전거를 조립하는 흐름에서, 1칸 부품과 체력 기반 공급이 기존 C안보다 반복 조작을 간단하게 만드는가?

사장님이 거래처에 주문한 혼합 부품 상자에서 알바가 하나씩 부품을 꺼냅니다. 공급 버튼은 `입고 정리`이며, 랜덤인 것은 종류·레벨입니다. 위치는 보드 하단 중앙 상자를 기준으로 가장 가까운 빈칸부터 결정합니다(격자 거리 제곱, 동률은 칸 인덱스 순). 다음 칸은 점선으로 표시합니다. 상자는 보드 밖에 있어 칸을 차지하지 않습니다.

## 유지하는 컨셉
프레임·휠셋·구동계·핸들바 4종과 Lv.1~4를 유지합니다. 완성차는 머지하지 않고, 요구 레벨 이상의 부품을 직접 장착하여 조립·납품합니다. 급여 500 C와 3단계 드림 바이크 성장을 독립 데모에서 연결합니다. 기존 통합 성장 저장소를 변경하지 않습니다.

## 핵심 규칙
- 보드 6×7, 모든 부품은 1칸. 탭 선택 후 대상 탭 또는 포인터 드래그로 이동·교환.
- 동일 종류·동일 레벨 2개를 드래그해 겹치면 대상 칸에서 다음 레벨 1개로 즉시 머지. 인접 조건·머지 버튼·자동 연쇄는 없음.
- 빈칸 드롭은 이동, 다른 종류·레벨 드롭은 위치 교환. 같은 Lv.4는 머지하지 않고 교환. 자기 칸·보드 밖·포인터 취소는 부품 소모 없음.
- 드래그 중 부품이 포인터를 따라가고, 놓을 칸에 머지/이동/교환을 표시. 탭 선택 후 대상 탭도 동일 규칙. 선택 시 일치하는 부품 전체 강조.
- 하단 중앙 입고 상자 버튼, 다음 위치 점선과 상자→칸 생성 연출. 연출은 reduced-motion 설정을 존중. 보드가 가득 차면 상자 비활성화.
- 30 체력으로 시작, 입고당 1 차감. 이동·머지·장착은 무료. 체력이 없거나 빈칸이 없으면 공급과 차감을 함께 차단.
- 실제 시간 10분당 1 회복. 오프라인 경과 시간과 미완료 회복 간격 보존. 최대 30, 만충 이후 시간은 비축하지 않음. Day와 별도.
- 입고 레벨: Lv.1 80%, Lv.2 20%. 종류: 70%는 미장착 종류 중 균등, 30%는 전체 4종 중 균등. 미장착 종류가 4회 연속 나오지 않으면 다음 공급에 보장. 개별 특정 종류의 천장은 아님.
- 첫 주문은 지급 부품만으로 완료 가능. 이후 3종의 요구 레벨 Lv.1~2 주문을 순환. 남은 부품은 보존.
- 재고 반납은 확인 후 부품 삭제, 체력 환급 없음. 잘못 장착하거나 미완성 납품은 차단.
- D안 전용 localStorage 저장. 유효하지 않은 데이터는 초기 상태 복구, 저장 불가 시 화면에 안내. 단일 탭 실험이며 다중 탭·서버 시간 검증은 범위 밖.
- 랩 도구: 체력 충전, 화면 내 10초당 1 회복 가속(재진입 시 OFF), 확인을 거치는 D안 초기화.

## 비교 대상과 평가
기존 C안과 동일한 자전거 조립 목표·부품 4종·레벨 체계를 비교합니다. 공급/머지 규칙이 달라 주문 난이도는 완전히 동일하지 않습니다. 수치 확정이나 속도 우열을 단순 비교하지 않습니다.

- 첫 주문을 설명 없이 완주할 수 있는가?
- 탭·드래그·머지 대상 강조가 의도대로 작동하는가?
- 랜덤 입고가 기대감을 주는가, 필요한 종류가 안 나와 답답한가?
- 공급·머지 횟수, 납품 수, 정체 시간을 기록한다.
- 체력이 0이어도 남은 부품으로 할 일이 있는가?
- 기존 C안 대비 조립 알바라는 느낌과 재플레이 의향을 평가한다.

## 실행 방법
Lab → MVP 핵심 플레이 → 머지 코어 → D안 → 체험 화면.
직접 경로: `#/track/merge-core/intake-merge/demo`.
첫 주문: 좌상단 프레임 2개 겹치기·장착 → 휠셋 2개 겹치기·장착 → 구동계·핸들바 장착 → 납품 → 내 드림 바이크 성장.
테스트 도구는 조작 안내 안에 있습니다. 상단 초기화도 D안 저장을 확인 후 초기화합니다.

## 검증 결과
자동 규칙 테스트: 첫 주문 완주·중복 납품·성장 비용, 거리 무관 겹치기·2개 소비·최대 레벨 교환, 최대 레벨, 포화/체력 차감, 공급 보정, 오프라인 회복·만충·시계 역행, 저장 손상, 이동·잔여 부품 보존.
DOM 이벤트 테스트로 탭 완주, 드래그 고스트·대상 피드백·단일 머지, 이동·교환, 보드 밖 드롭·터치 취소, 회복 중 드래그 유지, 저장 복구·포화 차단·화면 이탈 정리를 검증합니다. DOM 테스트는 실제 모바일 렌더링 검증을 대체하지 않습니다. 빌드 및 검증 결과는 PR에 기록합니다. 실제 사용자 C/D 비교, 장기 밸런스, 앱인토스 실기기 검증은 후속입니다.

## 기준 자료와 메인 반영
첨부 머지게임 설계안의 부품→조립→급여 흐름과 2-to-1을 유지합니다. v1의 3개 인접 선택 후 버튼 방식은 사용자 피드백에 따라 v2에서 대체했습니다. 3개 머지라고 별도 버튼이 필수인 것은 아니며, v1의 버튼은 초기 실험의 설계 선택이었습니다.

Travel Town 공식 [Board Items](https://support.traveltowngame.com/hc/en-us/articles/4833684165522-What-are-Board-Items)는 생성기를 눌러 부품을 만들고 동일 부품 2개를 드래그하여 겹치는 방식을 안내합니다. [Merge Board](https://support.traveltowngame.com/hc/en-us/articles/4833664499090-The-Merge-Board)는 생성기와 에너지의 연결을 설명합니다. 이를 이번 에너지·고객 주문 중심 코어의 참고로 삼았습니다. 모든 머지게임이 같은 규칙을 쓰는 것은 아닙니다. 공식 안내에는 세부 빈칸 선택 알고리즘이 없으므로 상자 가까운 칸 우선은 이 실험의 선택입니다.

v1 저장 키와 데이터 형식을 유지하여 기존 부품·장착·급여·성장을 그대로 복구합니다. 레벨업 비용은 3개에서 2개로 줄었으므로 고레벨 주문 요구치·체력 수치는 후속 밸런스 대상입니다. v1 구현은 PR #244 이력에서 확인할 수 있습니다.
일반 프로젝트 반영은 비교 후 별도 결정합니다. 이번에는 Lab 프로토타입만 추가합니다.
