# 머지 코어 D v3 · 입고 상자·겹치기 머지·직접 장착

- 실험 ID: game-core / merge / prototype-d / v3
- 상태: 검토 준비. 최종 채택과 수치 확정은 하지 않습니다.
- Lab 이슈: [#254](https://github.com/aigemro/dream-bike-garage-lab/issues/254) · 이전 버전 [#245](https://github.com/aigemro/dream-bike-garage-lab/issues/245)(v2) · [#243](https://github.com/aigemro/dream-bike-garage-lab/issues/243)(v1)
- 메인 질문: [머지 규칙 #27](https://github.com/aigemro/dream-bike-garage/issues/27), [최종 적용 #30](https://github.com/aigemro/dream-bike-garage/issues/30)

## 질문
일반 프로젝트의 실제 게임 화면과 같은 구성에서, 자유 이동·거리 무관 합성과 직접 장착이 자전거 가게 알바의 조립 재미를 만드는가?

## 가설
장르에서 익숙한 방식처럼 보드 어디에 있든 같은 부품 2개를 겹쳐 합성하고, 요구 레벨이 된 부품을 플레이어가 직접 자전거에 장착하면 "조립한다"는 손맛이 생깁니다. E안(이동 금지·인접 합성·자동 장착)과 같은 화면·주문으로 비교하면 자유도와 계획성 중 무엇이 더 재미있는지 볼 수 있습니다.

## v2 → v3 변경
### 1. 화면: 게임 화면 디자인 B안 정렬
E v3와 같은 공통 화면 모듈(`merge-play-screen.ts`)로 다시 만들었습니다. `game-screen-mobile.ts`(메인 출시 흐름의 플레이 화면)의 배치 수치·팔레트·부품 표현을 그대로 씁니다.

| 영역 | 일반 프로젝트 게임 화면 (B안) | D v3 |
|---|---|---|
| 캔버스 | Phaser 390×810 세로, FIT | 같음 (v2는 DOM 화면) |
| 헤더 | 크림 바 + 빨간 `WORK` 태그 + "두리 자전거 공방 · 작업대" + 우측 지표 | 같음, 우측 지표는 `급여 n C · 머지 n` |
| 주문 카드 | `NEW ORDER` 리본, 주문명, 부품 칩 4개(픽셀 아이콘·Lv), 픽셀 자전거(미장착 50%) | 같음 + 납품 보상, 장착할 수 있는 칩은 초록 `장착!` |
| 보드 | 나무 테두리 6×7, 셀 52, 크림 셀 | 같음 + 점선 `다음 입고` 칸 |
| 부품 | 부품 대표색 블록 + 픽셀 아이콘 + Lv 배지 | 같음 (모든 부품 1칸) |
| 장착 | 목표 레벨이 되면 자동 장착, 자전거 부위로 비행 | 직접 장착(아래 참고), 비행 연출은 같음 |
| 하단 선반 | `택배 선반 · DELIVERY` + 카테고리 택배 4개 | 같은 자리·크기에 `입고 상자 · INTAKE BOX` + 입고 상자 열기·장착·반납, 알바 체력·작업대 정보 |
| 입력 | 탭 선택 → 대상 탭, `× 선택 취소` | 같음 + 드래그 놓기 |
| 효과음 | `release-audio` | 같음 (랩 체험은 효과음만) |

### 2. 주문: 일반 프로젝트 3종 (E v3와 동일)
통학용 어반 로드(2·2·1·1, 1,000 C) → 트레일 MTB(3·2·2·1, 1,400 C) → 엔듀런스 로드(2·3·2·2, 1,800 C)를 순환합니다. v2의 Lab 전용 주문(요구 Lv.1~2, 급여 500)은 쓰지 않습니다.

### 3. 입고 순서: 가운데 → 바깥 (E안과 동일)
v2는 보드 아래 중앙 상자에서 가까운 칸부터 채웠습니다. v3는 보드 가운데 두 칸에서 시작해 바깥 고리로 나가고, 같은 고리 안에서는 12시 방향부터 시계 방향으로 채웁니다. 비운 가운데 칸이 생기면 그 칸을 다시 먼저 씁니다.

### 4. 흐름 정리
- 장착 방법: [장착] 버튼, 주문 카드의 해당 부품 칩 탭, 부품을 주문 카드로 끌어 놓기 중 하나
- 납품: v2의 별도 [자전거 납품] 버튼 대신, 메인 흐름처럼 4종을 장착하면 자동 납품하고 급여를 지급합니다.
- 메인 플레이 화면 구성에 맞춰 드림 바이크 성장 버튼은 뺐습니다(성장은 홈·메타 화면 몫).
- 반납 확인은 브라우저 확인 창 대신 게임 화면 안에서 [반납]을 두 번 눌러 확인합니다.
- 랩 도구(체력 충전·10초 회복·초기화·통계)는 캔버스 밖 접이식 영역으로 옮겼습니다.

## 핵심 규칙
1. 보드 6×7, 모든 부품은 1칸입니다.
2. 입고 상자를 열면 체력 1을 쓰고, 다음 입고 칸(가운데 → 바깥)에 랜덤 부품 1개를 꺼냅니다. 빈칸이나 체력이 없으면 추첨·차감하지 않습니다.
3. 입고 확률은 E안과 같습니다: Lv.1 80%·Lv.2 20%, 미장착 종류 70% 우선, 미장착 종류가 4회 연속 안 나오면 다음 입고에서 보장.
4. 부품을 고른 뒤 다른 칸을 누르면(또는 끌어 놓으면) 같은 종류·같은 레벨은 대상 칸에서 다음 레벨로 합성(거리 무관), 빈칸은 이동, 다른 부품은 자리 교환입니다. Lv.4끼리는 교환하고, 옆에 놓아도 자동 합성은 없습니다.
5. 요구 레벨 이상이면서 아직 장착하지 않은 종류만 장착할 수 있습니다. 4종을 장착하면 자동 납품·급여 지급 후 다음 주문으로 넘어가며, 남은 부품은 보드에 그대로 둡니다.
6. 반납은 부품을 지우며 체력은 돌려주지 않습니다.
7. 체력 30, 실제 10분당 1 회복(오프라인 포함, 가득 찬 뒤 시간은 쌓지 않음).
8. 저장 키는 v1·v2와 같고, 이전 저장은 성장 값을 빼고 v3로 옮깁니다.

## 비교 조건
[E v3](merge-placement.md)와 같은 화면 구성(`merge-play-screen`), 같은 주문 3종·입고 순서·체력·입고 확률(`merge-core-shared`)을 씁니다. 달라지는 것은 이동 규칙(자유 이동·교환), 합성 조건(거리 무관), 장착 방식(직접 장착), 연쇄 보너스 유무입니다. D안에는 연쇄 보너스를 넣지 않았습니다. 이동이 자유로우면 합성을 모아 이어 가기 쉬워 무료 상자가 체력 경제를 무너뜨리기 때문입니다.

## 규칙 시뮬레이션 참고
각 방안의 규칙 모듈을 그대로 사용해 주문 40건 × 300회를 근사 플레이했습니다. 실제 사용자 데이터가 아닙니다.

| 방안 · 플레이 방식 | 주문당 체력 | 최대 점유 | 막힘 경험 회차 |
|---|---|---|---|
| D v3 · 요구 레벨에 필요한 쌍만 합성하고 바로 장착 | 6.90 | 7.8/42 | 0% |
| E v3 · 합성 가능하면 바로 합성 | 7.20 | — | 6% |
| E v3 · 합성을 모았다가 한 번에(연쇄 보너스) | 6.66 | — | 13% |

- D안은 위치 제약이 없어 막히지 않지만, 보드가 대부분 비어 있어 공간 판단 요소는 약합니다.
- 체력만 보면 D안이 E안의 바로 합성보다 적게 쓰고, E안의 모아서 연쇄보다는 많이 씁니다.

- [ ] 가운데에서 바깥으로 채워지는 입고가 자연스럽고 다음 위치를 예측하기 쉬운가?

## 실행 방법
Lab → MVP 핵심 플레이 → 머지 코어 → **D v3: 입고 상자 · 겹치기 머지 · 직접 장착**

`#/track/merge-core/intake-merge/demo`

1. 첫 주문: 좌상단 프레임을 누른 뒤 옆 프레임을 눌러 Lv.2 합성 → 초록 `장착!` 칩 확인 → [장착]
2. 구동계는 주문 카드로 끌어 놓아, 핸들바는 고른 뒤 주문 칩을 눌러 장착
3. 휠셋 2개를 합성해 장착 → 납품 도장과 1,000 C, 트레일 MTB 전환 확인
4. 입고 상자를 여러 번 열어 가운데 칸부터 바깥으로 채워지는지 확인
5. 빈칸 이동, 다른 부품과 자리 교환, 떨어진 같은 부품 합성, [반납] 두 번 누르기를 확인

랩 도구는 화면 아래 `LAB 도구`를 펼쳐 사용합니다. 상단 `초기화`도 D안 저장을 확인 후 초기화합니다.

## 검증 결과
- 자동 테스트: D 규칙 13건(첫 주문·장착 차단·납품 후 부품 보존·거리 무관 합성·교환·무효 놓기·자동 합성 없음·가운데 입고·막힘·반납·복구·v1 이전·손상 저장), D 입력 판정 5건, D·E 공통 모듈 9건. 전체 Vitest 143건과 `npm run build` 통과(기존 번들 크기 경고 유지).
- 브라우저 확인: 실행 방법 1~4를 개발 서버에서 직접 진행했습니다. 합성 후 칩 강조와 [장착] 활성화, 세 가지 장착 방법, 자동 납품 도장과 다음 주문 전환, 입고 순서(가운데 21번 → 20번 → 15번 칸)를 확인했습니다.
- 한계: 미리보기 창이 가려진 상태에서는 프레임이 거의 그려지지 않아, 연출 확인은 개발 서버에서만 임시 타이머 루프로 진행했습니다(커밋에는 포함하지 않음). 실제 휴대폰·앱인토스 실기기, 장기 반복 재미, 체력 밸런스는 후속 검증 대상입니다. v2의 DOM 조작 테스트는 화면이 Phaser 캔버스로 바뀌어 규칙·입력 판정 테스트로 대체했습니다.

## 비교 요약
- 나은 점: 장르에서 익숙한 자유 이동·겹치기라 처음 이해하기 쉽고, 막힘이 거의 없습니다. 직접 장착으로 조립 단계를 플레이어가 마무리합니다.
- 불리한 점: 위치가 의미 없어 보드 공간 판단이 약하고, 장착 조작이 4번 더 필요합니다. 연쇄 보너스 같은 계획 요소가 없습니다.
