## 질문
일반 프로젝트의 실제 게임 화면과 같은 구성에서, 다음 입고 칸을 읽고 합성 방향과 연쇄를 계획하는 과정이 작업대 퍼즐의 재미를 만드는가?

## 가설
E v2는 규칙은 검증할 수 있었지만 화면이 순수 DOM(유니코드 아이콘·선 자전거·베이지 카드)이라 메인 게임 화면과 비교하기 어려웠습니다. 또한 Lab 전용 주문(요구 Lv.1~2)에서는 주문당 합성이 약 1.3회뿐이라 배치 판단이 드러나지 않았습니다. 메인과 같은 화면과 주문을 쓰고, 상자를 열기 전 합성을 모아 이어 가는 연쇄 보상을 두면 "언제 상자를 열고 언제 합성할지"라는 선택이 생길 것으로 봅니다.

## v2 → v3 변경
### 1. 화면: 게임 화면 디자인 B안 정렬
`game-screen-mobile.ts`(메인 출시 흐름의 플레이 화면)의 배치 수치·팔레트·부품 표현을 그대로 사용합니다.

| 영역 | 일반 프로젝트 게임 화면 (B안) | E v3 |
|---|---|---|
| 캔버스 | Phaser 390×810 세로, FIT | 같음 |
| 헤더 | 크림 바 + 빨간 `WORK` 태그 + "두리 자전거 공방 · 작업대" + 우측 지표 | 같음, 우측 지표는 `급여 n C · 머지 n` |
| 주문 카드 | `NEW ORDER` 리본, 주문명, 부품 칩 4개(픽셀 아이콘·Lv), 픽셀 자전거(미장착 50%) | 같음 + 납품 보상 표시 |
| 보드 | 나무 테두리 6×7, 셀 52, 크림 셀 | 같음 + 점선 `다음 입고` 칸 |
| 부품 | 부품 대표색 블록 + 픽셀 아이콘 + Lv 배지 | 같음 (모든 부품 1칸) |
| 장착 연출 | 부품 색 사각형이 자전거 부위로 520ms 비행 | 같음 |
| 하단 선반 | `택배 선반 · DELIVERY` + 카테고리 택배 4개 | 같은 자리·크기에 `부품 상자 · PARTS BOX` + 상자 열기·되돌리기·반품, 알바 체력·연쇄 합성 |
| 입력 | 탭 선택 → 대상 탭, `× 선택 취소` | 같음 + 드래그 놓기도 같은 규칙 |
| 효과음 | `release-audio`의 tap·parcel·merge·install·complete·reward·error | 같음 (랩 체험은 효과음만) |

랩 도구(체력 충전·10초 회복·초기화·통계)는 게임 디자인과 섞이지 않도록 캔버스 밖 접이식 영역으로 옮겼습니다.

### 2. 주문: 일반 프로젝트 3종
| 주문 | 프레임·휠셋·구동계·핸들바 요구 레벨 | 보상 |
|---|---|---|
| 통학용 어반 로드 | 2·2·1·1 | 1,000 C |
| 트레일 MTB | 3·2·2·1 | 1,400 C |
| 엔듀런스 로드 | 2·3·2·2 | 1,800 C |

이름·보상·자전거 종류는 `meta-progress`의 `ORDER_METAS`, 요구 레벨은 메인 `ORDERS`와 같은 값입니다. 플레이 화면에 성장 버튼이 없는 메인 구성에 맞춰 v2의 드림 바이크 성장 버튼은 뺐습니다(성장은 홈·메타 화면 몫).

### 3. 게임성 보강: 연쇄 합성 보너스
- 상자를 열지 않고 이어서 합성한 횟수를 `연쇄`로 셉니다. 상자를 열면 0으로 돌아가고, 반품은 연쇄를 끊지 않습니다.
- 3연쇄: 무료 상자 1개 (다음 상자를 체력 없이 엽니다. 보관 개수 제한 없음)
- 5연쇄: 필수 부품 확정 1회 (다음 상자에서 아직 장착하지 않은 종류가 나옵니다)
- 메인 설계서 6.4의 "연속 머지 콤보"를 시간 기준 대신 "상자 사이 연속 합성" 기준으로 옮긴 것입니다. 이동이 없는 E안에서는 빠른 입력보다 합성을 모아 두는 계획이 실력 요소가 되기 때문입니다.

### 4. 규칙 보완
- 납품 직후 다음 주문을 이미 채운 부품을 같은 행동에서 바로 장착합니다. v2는 다음 행동까지 장착이 미뤄져 "완성 즉시 장착" 안내와 어긋났습니다. 남은 부품으로 다음 주문까지 완성되면 연속 납품합니다.
- 요구 레벨 이상 부품 중 가장 낮은 레벨부터 장착해 상위 부품을 아낍니다(v2는 칸 순서 기준).
- 시작할 때 이미 요구를 채운 부품(첫 주문의 Lv.1 구동계·핸들바)은 바로 장착합니다.

## 핵심 규칙
1. 비어 있는 칸 중 보드 가운데(3·4열 사이, 4행)에 가까운 칸이 `다음 입고`입니다. 가운데 두 칸에서 시작해 바깥 고리로 나가고, 같은 고리 안에서는 12시 방향부터 시계 방향으로 채웁니다(D안과 같은 순서).
2. 상자를 열면 체력 1(무료 상자가 있으면 무료 상자)을 쓰고 랜덤 부품 1개를 그 칸에 바로 놓습니다. 빈칸이나 체력이 없으면 추첨·차감하지 않습니다.
3. 놓인 부품은 이동·교환할 수 없습니다. 상하좌우의 같은 종류·같은 레벨 2개를 겹치면 대상 칸에 다음 레벨이 남습니다. 대각선·Lv.4 합성·자동 연쇄 합성은 없습니다.
4. 주문 레벨 이상 부품은 행동 직후 자동 장착되고, 4종이 모이면 자동 납품·급여 지급 후 다음 주문으로 넘어갑니다.
5. 되돌리기는 최근 합성·반품 1회를 자동 장착·납품·연쇄 보너스까지 한 번에 되돌립니다. 새 상자를 열면 기록이 지워져 재추첨할 수 없습니다.
6. 반품은 선택 부품을 두 번 눌러 확인한 뒤 제거하며 체력은 돌려주지 않습니다.
7. 체력 30, 상자당 1, 실제 10분당 1 회복(오프라인 포함). 입고 확률은 v2와 같습니다(Lv.1 80%·Lv.2 20%, 미장착 종류 70% 우선, 4회 미출현 보장).
8. 저장 키는 v1·v2와 같고, 이전 저장은 v3 규칙으로 한 번 정리해 이어서 진행합니다.

## 연쇄 기준값 근거 (규칙 시뮬레이션)
E v3 규칙 모듈을 그대로 사용해 주문 40건 × 300회를 근사 플레이했습니다. 실제 사용자 데이터가 아니라 기준값을 고르기 위한 참고치입니다.

| 플레이 방식 | 주문당 체력 | 주문당 무료 상자 | 막힘 경험 회차 | 체력 1당 급여 |
|---|---|---|---|---|
| 합성 가능하면 바로 합성 | 7.20 | 0.00 | 6% | 193 C |
| 합성을 3쌍 이상 모았다가 한 번에 | 6.66 | 0.76 | 13% | 209 C |

- 바로 합성하면 연쇄는 2를 넘기 어려워 보너스가 거의 없습니다.
- 모았다가 이어 가면 체력이 약 7% 절약되지만, 보드가 차서 막힐 위험이 두 배가 됩니다. 위험과 보상이 맞물린 선택이 생깁니다.
- 5연쇄(필수 부품 확정)는 주문당 0.06회로 드문 목표입니다.
- 위 수치는 가운데→바깥 입고 기준입니다(이전 아래 중앙 입고: 7.18 / 6.68, 막힘 5% / 11%로 큰 차이 없음).
- 같은 주문·입고 순서의 D v3는 주문당 체력 6.90, 막힘 0%입니다. 모아서 연쇄하면 E안이 D안보다 체력을 덜 쓰지만, 바로 합성하면 더 씁니다.
- 참고로 Lab 전용 주문(요구 Lv.1~2)에서는 주문당 합성이 1.3회, 최대 점유가 12/42칸이어서 v2로는 배치 판단의 차이가 드러나지 않았습니다.

## 비교 조건
[D v3](merge-intake.md)(자유 이동·거리 무관 겹치기·직접 장착)와 비교합니다. 두 방안은 같은 화면 구성(`merge-play-screen`), 같은 주문 3종·입고 순서·체력·입고 확률(`merge-core-shared`)을 쓰고, 달라지는 것은 이동 규칙·합성 조건·장착 방식·연쇄 보너스뿐입니다. 비교 시 체력 수치보다 판단의 질(예정 칸 읽기, 연쇄 계획, 막힘 대처)과 조작 피로를 중심으로 봅니다.

- 관련 버전: Phaser 3.90, Vite 7, Vitest 4

## 평가 기준
- [ ] 메인 게임 화면과 같은 화면으로 인식되고, 주문·보드·선반을 스크롤 없이 읽을 수 있다.
- [ ] 점선 칸을 보고 다음 합성을 준비한다(합성 방향을 고르는 이유를 설명할 수 있다).
- [ ] 연쇄 보너스를 이해하고, 모아서 이어 갈지 바로 합성할지 스스로 고른다.
- [ ] 이동 없이도 막힘이 과도하지 않고, 반품·되돌리기로 회복할 수 있다.
- [ ] 자동 장착·납품이 조립 성취를 약하게 만들지 않는다.

## 실행 방법
Lab → MVP 핵심 플레이 → 머지 코어 → **E v3: 예정 배치·인접 합성·연쇄**

`#/track/merge-core/placement-merge/demo`

1. 첫 주문: 좌상단 프레임 2개를 차례로 탭해 합성 → 자전거로 장착 → 휠셋 2개 합성 → 납품 도장과 1,000 C 확인 → 트레일 MTB로 전환
2. 점선 칸 확인 → 부품 상자 열기 → 상자에서 점선 칸으로 부품이 들어오는지 확인
3. 상자를 열지 않고 합성 3회 → "3연쇄! 다음 상자 무료" 배너와 상자 버튼의 `무료 ×1` 확인 → 상자를 열어 체력이 줄지 않는지 확인
4. 부품 선택 → 반품 두 번 → 되돌리기로 복구
5. 빈칸·떨어진 부품으로 드래그하면 이동하지 않고 이유를 안내하는지 확인

랩 도구는 화면 아래 `LAB 도구`를 펼쳐 사용합니다. 상단 `초기화`도 E안 저장을 확인 후 초기화합니다.

- 자동 테스트: 규칙 19건(주문 데이터·시작 장착·첫 주문·납품 직후 장착·연속 납품·최소 레벨 장착·입고·막힘·인접성·연쇄 무료 상자·확정 부품·되돌리기·반품·회복·저장 복구·v1/v2 이전), 입력 판정 6건, D·E 공통 모듈 9건(입고 순서·주문·체력·입고 추첨). 전체 Vitest와 `npm run build` 통과(기존 번들 크기 경고 유지).
- 2026-10-07 조정 후 브라우저 확인: 시작 시 점선이 가운데 칸에 있고, 상자를 열 때마다 가운데에서 바깥으로 채워지는 것을 확인했습니다.
- 브라우저 확인: 위 실행 방법 1~5를 개발 서버에서 직접 진행했습니다. 선택·합성 하이라이트, 장착 비행, 납품 도장, 다음 주문 전환, 3연쇄 배너, 무료 상자 입고, 반품 확인·되돌리기, 드래그 거부 안내를 확인했습니다.
- 한계: 미리보기 창이 가려진 상태에서는 브라우저가 프레임을 거의 그리지 않아, 연출 순서 확인은 개발 서버에서만 임시로 타이머 루프를 켜고 진행했습니다(커밋에는 포함하지 않음). 실제 휴대폰·앱인토스 실기기, 장기 반복 재미, 수급 확률·체력 밸런스는 후속 검증 대상입니다. 화면이 Phaser 캔버스로 바뀌어 v2의 DOM 조작 테스트는 규칙·입력 판정 테스트로 대체했습니다.

## 비교 요약
- 나은 점: 메인 화면과 같은 구성이라 채택 시 화면 차이를 따로 판단할 필요가 없습니다. 연쇄 보너스로 "바로 합성 vs 모아서 연쇄"라는 선택이 생깁니다.
- 불리한 점: 이동이 없어 주문 레벨이 더 깊어지면(Lv.3~4 중심) 막힘이 빠르게 늘어납니다. 메인 주문 기준에서도 막힘을 겪는 회차가 5~11% 있습니다.

## 다음 게임성 후보 (미구현)
레퍼런스 머지 게임 조사에서 이 구조에 옮기기 좋은 후보입니다. 채택 여부는 메인에서 결정합니다.
- 덮개 칸·녹슨 부품: 옆에서 합성하면 열리는 칸으로 초반 보드를 좁히고 확장 성장감을 줍니다.
- 넘침 보관: 작업대가 가득 찰 때 입고 부품을 잠시 보관해 막힘을 유예합니다(보상형 광고 연결 후보).
- 만능 부품·분해 공구: 주문·레이스 보상으로 지급해 운에 의한 막힘을 줄입니다.
- 하트 연계: 알바 체력을 메인 하트 규칙([메인 #73](https://github.com/aigemro/dream-bike-garage/issues/73))과 같은 값으로 맞추고, 무료 상자를 광고 보상과 같은 단위로 다룹니다.
