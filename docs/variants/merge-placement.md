## 질문과 가설
자유 이동 D안에서 약해진 배치 판단을 직접 배치와 인접 합성으로 강화할 수 있는가?
부품을 처음 놓은 위치와 합성 결과가 남는 방향을 선택하면, 에너지가 충분해도 작업대 공간을 계획하는 재미가 생길 것으로 예상한다. 체감 재미는 아직 사용자 검증 전이다.

## 비교 대상과 공통 조건
D v2의 자동 배치·자유 이동·거리 무관 겹치기와 비교한다. 초기 6×7 보드와 부품 8개, 4종/Lv.1~4, 주문 3종 순환, 체력 30·10분 회복, 공급 확률, 납품 500 C·성장 3단계는 동일하다. E는 새 경로·저장을 사용하며 D를 변경하지 않는다.

## 규칙
1. 상자를 열면 체력 1을 소비해 랜덤 부품 1개를 보드 밖 입고 대기에 생성한다. 대기가 차 있거나 보드 빈칸이 없거나 체력이 부족하면 추첨·차감하지 않는다.
2. 입고 대기 부품을 원하는 빈칸에 드래그하거나 대기 선택 후 빈칸을 탭한다. 선택 취소는 부품을 버리지 않는다. 놓기 전 반투명 미리보기와 합성 가능한 이웃을 보여준다.
3. 배치한 부품의 일반 이동·교환은 금지한다. 상하좌우 동일 종류·동일 레벨 2개만 겹칠 수 있다. 결과는 대상 칸에 남고 출발 칸은 빈다. 대각선·행 경계 연결·Lv.4 합성·자동 연쇄는 없다. 탭 선택 후 인접 대상 탭도 동일하다.
4. 보류 1칸을 누르면 입고 부품을 보관, 저장된 부품을 꺼내기, 또는 입고/보류 교환한다. 보드 부품을 보류로 옮길 수 없다.
5. 최근 배치·합성·보류·장착·납품·성장·반품 중 한 행동을 1회 되돌린다. 새 공급은 되돌릴 수 없고 기존 이력도 지운다. 배치 되돌리기는 이미 뽑힌 동일 부품을 대기로 복구한다. 체력·회복 시각·공급 추첨 카운터는 되돌리지 않는다. 되돌리기 이력도 저장한다.
6. 보드가 막히면 합성·장착 또는 선택 부품 반품으로 공간을 확보한다. 반품은 확인 후 부품만 제거하며 체력 환불은 없다. 직전 반품은 되돌릴 수 있다. 광고/유료 복구는 이번 범위 밖이다.
7. 요구 레벨 이상의 부품을 직접 장착 → 네 부품 완성 시 납품 → 급여 → 내 드림 바이크 성장으로 연결한다.

공급 확률: Lv.1 80% / Lv.2 20%, 종류는 70% 미장착 종류 중 균등, 30% 전체 종류 중 균등. 미장착 종류가 4회 연속 안 나오면 다음에 미장착 종류를 보장한다. 특정 종류별 천장은 아니다. 실제 시간 회복은 Day와 독립적이다. 테스트 충전·10초 가속은 안내 안에 제공한다.

## 실행 및 확인 순서
Lab → MVP 핵심 플레이 → 머지 코어 → **E안: 직접 배치·인접 합성**

`#/track/merge-core/placement-merge/demo`

- 상자 열기 → 대기 부품 확인 → 빈칸 위 미리보기 → 배치 → 되돌리기 → 같은 부품 재배치.
- 초기 프레임 1→0, 휠셋 3→2 합성 후 0·2·4·5번 칸 장착 → 납품 → 성장. 좌상단이 0번 칸이다.
- 떨어진 부품·대각선·빈칸에 드래그하면 원래 부품이 보존되는지 확인.
- 보류 → 추가 공급 → 보류 교환 → 새로고침 후 복원.
- 보드 포화 시 반품으로 공간 확보. 되돌리기 시 부품과 빈칸이 함께 복원되는지 확인.

## 평가 기준
- 배치 위치·합성 방향을 실제로 고민하는가?
- 대기/보류/보드 사이의 조작을 쉽게 이해하는가?
- 잘못 놓은 부품 때문에 진행 불가 상태가 오래 지속되는가?
- D안과 자전거 3대 완성 시간, 공급·합성·반품 횟수, 조작 피로 비교.
- 에너지 충분 조건에서 먼저 재미를 평가한 뒤 체력 소비량을 조절한다.

## 검증과 한계
순수 규칙과 DOM 포인터/탭 테스트로 입고 차감, 배치, 인접성, 이동 금지, 보류, 재추첨 방지, 되돌리기와 보상 무결성, 저장·회복·취소·화면 이탈을 검증한다. 전체 Vitest 104건(E안 22건 포함)과 `npm run build`가 통과했다. 현재 환경에는 실행 가능한 Chromium이 없어 실제 브라우저 화면·터치 검증은 미완료다. DOM 테스트가 실기기 검증을 대체하지 않는다. 기존 Vite 번들 크기 경고는 유지된다.
실제 사용자의 장기 반복 재미, 수급 확률·보드 크기 밸런스, 앱인토스 실기기는 후속이다. 3개 합성 비교는 이번 범위 밖이다.

## 참고 자료와 적용 구분
[Triple Town 개발사 가이드](https://support.spryfox.com/hc/en-us/articles/219104828-How-to-play-Triple-Town)의 랜덤 오브젝트 제공 → 빈칸 직접 선택과 보관함을 참고했다. 원작의 자동 3개 합성을 그대로 구현한 것이 아니다. E안의 수동 인접 2개 합성·반품·되돌리기는 이번 사용자 합의안이다.

첨부 Dream Bike Garage 설계안의 자전거 부품 합성→조립→급여 개념과 부품 레벨을 유지한다. 결론은 사용자 D/E 비교 후 결정하며 일반 프로젝트에는 아직 적용하지 않는다.
