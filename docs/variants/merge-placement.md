## 질문과 가설
원하는 빈칸을 직접 고르는 E v1은 선택권이 있지만 입고 대기·보류·배치·장착·납품 버튼이 모바일 화면을 길게 만든다. E v2는 다음 입고 칸을 미리 공개하고 이후 배치를 자동화한다. 플레이어는 예정 위치를 보고 인접 합성을 준비하며, 직접 해야 하는 조작을 상자 개봉과 합성에 집중한다.

## 비교 조건
D v2의 자동 배치·자유 이동·거리 무관 겹치기, E v1의 직접 배치·이동 제한과 비교한다. 6×7 보드, 부품 4종/Lv.1~4, 주문 3종, 체력 30·10분 회복, 공급 확률, 납품 500 C·성장 3단계는 동일하다. D안 코드는 변경하지 않는다.

## 규칙
1. 비어 있는 칸 중 보드 아래 중앙에 가까운 칸을 `다음 입고`로 표시한다. 거리가 같으면 왼쪽 칸을 먼저 쓴다.
2. 상자를 열면 체력 1을 소비해 랜덤 부품 1개를 예정 칸에 바로 배치한다. 빈칸이나 체력이 없으면 추첨·차감하지 않는다.
3. 일반 이동·교환은 금지한다. 상하좌우의 동일 종류·동일 레벨 2개를 겹칠 때만 합성하며 결과는 대상 칸에 남는다. 대각선, Lv.4 합성, 자동 연쇄는 없다.
4. 주문 레벨 이상 부품은 행동 판정 직후 자동 장착한다. 네 종류가 장착되면 자동 납품하고 500 C를 지급한다. 한 행동에서는 한 주문만 납품하여 남은 부품의 연쇄 소비를 막는다.
5. 최근 합성·반품·성장은 작업대 안의 작은 버튼으로 1회 되돌린다. 합성과 함께 발생한 자동 장착·납품·보상도 한 행동으로 되돌린다. 새 공급은 되돌릴 수 없으며 기존 이력을 지워 재추첨을 막는다.
6. 반품은 선택 부품을 확인 후 제거하며 체력을 돌려주지 않는다. 기존 E v1의 대기·보류 부품은 첫 로드 때 새 예정 위치 순서로 보드에 옮겨 저장한다.

입고·합성·장착·납품은 각각 `dbg:merge-motion` 상태 이벤트를 보낸다. 현재는 짧은 CSS 피드백만 적용하며, 본 프로젝트 디자인 단계에서 같은 이벤트에 부품 이동 경로, 장착 슬롯 흡수, 완성 자전거 출고 모션을 연결할 수 있다. `prefers-reduced-motion`도 적용한다.

## 평가 기준
- 다음 입고 위치를 보고 합성 계획을 미리 세우는가?
- 자유 이동 없이도 막힘이 과도하지 않은가?
- 자동 장착·납품이 조립 성취를 약하게 만들지 않는가?
- 390×810에서 보드와 주문 정보를 한 화면에서 읽을 수 있는가?
- D v2/E v1과 자전거 3대 완성 시간, 공급·합성·반품 횟수, 조작 피로를 비교한다.

## 검증과 한계
순수 규칙과 DOM 테스트로 예정 칸 결정, 직접 입고, 인접성, 이동 금지, 자동 장착·납품, 한 행동 한 주문, 되돌리기/보상 무결성, 반품, v1 저장 이전, 회복과 화면 이탈을 검증한다. 전체 Vitest 101건과 프로덕션 빌드가 통과했다. 기존 Vite 번들 크기 경고는 유지된다. 실제 사용자의 장기 반복 재미, 수급 확률·보드 크기 밸런스, 앱인토스 실기기와 최종 애니메이션 품질은 후속 검증 대상이다.

첨부 Dream Bike Garage 설계안의 자전거 부품 합성→조립→급여 개념과 부품 레벨은 유지한다. 결론은 D/E 비교 후 메인 프로젝트에서 결정한다.
