# B안 · 활성 플레이 시간 + 계정별 진행

## 검증 가설

Day 제한은 실제 시계가 아니라 사용자가 게임 화면에서 플레이하는 시간에만 차감해야 짧은 세션의 긴장감과 중단 복귀의 안전성을 함께 제공할 수 있다. 계정과 게임 프로필을 분리하고 진행 상태를 `playerId` 단위로 저장하면 같은 기기에서 계정을 전환해도 각 사용자의 Day·재화·주문·성장을 독립적으로 복원할 수 있다.

## 이번 구현

- 비밀번호를 수집하지 않는 테스트 계정 A/B 로그인
- 최초 로그인 시 닉네임 기반 게임 프로필 생성
- Lab 테스트용 10초 활성 플레이 Day와 준비·진행·일시정지·정산·완료 상태
- 홈·플레이 화면 내부의 현재 Day, 남은 시간, 오늘 수입 표시
- 백그라운드, 화면 이탈, 로그아웃 시 타이머 일시정지와 자동 저장
- 시간 종료 또는 Lab용 `DAY 종료` 버튼을 통한 한 번만 적용되는 정산과 오늘 수입 확인
- 자전거 납품 후 별도 보상 화면 없이 보드 부품을 유지한 채 다음 주문 즉시 시작
- Day 번호, 남은 시간, 코인, 주문 번호, 성장, 수집 상태, 정산 이력을 계정별로 저장

## 체험 순서

1. 계정 A로 로그인하고 게임 닉네임을 만든다.
2. `PLAY`에서 Day를 시작하고 주문 또는 수동 Day 종료를 진행한다.
3. 로그아웃한 뒤 계정 B로 별도의 프로필과 진행을 만든다.
4. 계정 A로 다시 로그인해 이전 Day와 재화가 복원되는지 확인한다.
5. 플레이 도중 탭을 백그라운드로 보내 남은 시간이 줄지 않는지 확인한다.

## 비교 기준

- A안: 실제 시각 기준 마감 — 복귀 시 시간이 계속 흐르지만 이탈 페널티가 큼
- B안: 활성 플레이 시간 — 중단 복귀가 안전하고 MVP 테스트에 적합함
- C안: 행동 횟수 기준 — 시간 압박은 약하지만 밸런스와 규칙 설명 비용이 큼

## 프로토타입 경계

이번 Lab은 인증·세션·Day·계정별 저장 계약을 검증한다. 실제 Apps-in-Toss 인증과 서버 동기화는 `AuthProvider` 및 저장소 인터페이스의 후속 구현으로 남긴다. 기존 게임 화면의 임시 보드 배치는 Day를 벗어나면 초기화하며, 주문 번호와 보상·성장 상태만 이어진다.

상세 계약과 테스트 시나리오는 `docs/DAY_ACCOUNT_EXPERIMENT.md`에 기록한다.
