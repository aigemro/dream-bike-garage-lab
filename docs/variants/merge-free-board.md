# 자유 보드 2-to-1 머지

## 구현 방식
빈 칸에 부품을 생성하고 같은 단계의 부품 두 개를 선택해 상위 단계 하나로 합칩니다.

## 1차 구현 범위
- 마우스·터치를 함께 처리하는 Pointer 선택 입력
- 6×7 보드와 프레임·휠셋·구동계·핸들바 4종
- Lv.1~Lv.4 동일 종류·동일 단계 2-to-1 머지
- 자유 생성·선행 제작·공간 정리
- 시간·행동·머지·오입력·빈 칸 수 실시간 표시

## 2차 구현 범위
- 부품 선택 버튼을 보드 아래로 이동
- 열·행 숫자 옆의 − / + 버튼을 누르면 즉시 바뀌는 4~10 범위 가변 보드
- 보드의 부품을 한 번 눌러 선택하고, 같은 부품을 다시 눌러 90° 회전
- 선택한 부품 제거 기능은 제공하지 않음
- 프레임 3칸, 휠셋 2칸, 구동계 1칸, 핸들바 2칸의 부품별 점유 형태
- 선택한 부품의 90도 회전과 빈 공간 이동
- 부품 모양이 보드 밖으로 나가거나 다른 부품과 겹치는 배치 차단
- 여러 칸을 차지하는 동일 종류·동일 레벨 부품의 2-to-1 머지

## 6×7을 초기값으로 둔 이유
6×7은 확정된 게임 규격이 아니라 1차 비교를 위한 후보값입니다. 모바일 세로 화면에서 조작 가능한 셀 크기를 유지하면서 42칸의 공간 관리와 보드 막힘을 관찰하기 위해 사용했습니다. 2차 구현에서는 이 가정을 직접 비교할 수 있도록 열·행을 변경할 수 있습니다.

## 확인할 점
규칙 이해도, 공간 관리의 재미, 모바일 조작성을 확인합니다.

## 검토 의견 (2026-08-08)

### 의도 일치
가변 보드(4~10), 부품별 점유 형태, 선택→재클릭 90° 회전, 경계·겹침 배치 차단, 동일 종류·레벨 2-to-1 머지, 실시간 지표 등 1·2차 범위가 대체로 문서대로 구현되었습니다. 단, 2차 범위의 "부품 선택 버튼을 보드 아래로 이동"은 실제 코드에서 오른쪽 패널(`src/merge-prototype.ts:309-371`)에 있어 문서와 어긋납니다. 문서 또는 코드 중 한쪽 갱신이 필요합니다.

### 발견된 문제
- **안내 문구와 규칙 불일치**: "같은 부품 위에 놓으면 바로 머지됩니다"(`src/merge-prototype.ts:335`)라고 안내하지만 생성 배치 시 즉시 머지는 Lv.1 대상에만 동작합니다(`:377`). Lv.2 이상 부품 위에 놓으면 선택 동작으로 빠져, 오입력(mistakes) 지표에 "규칙 오해"가 아닌 "문구 오해"가 섞입니다.
- **배치 직후 재클릭 시 회전 상태 유지**: `selectGenerator`의 재선택 판정(`src/merge-prototype.ts:430`)이 배치 활성 여부를 확인하지 않아, 부품을 배치한 직후 같은 버튼을 다시 누르면 0°가 아닌 90° 회전 상태로 시작합니다. 의도가 아니라면 배치 활성 조건 추가 필요.
- **모바일 세로 검증 한계**: 캔버스가 1120×720 고정 + Scale.FIT이라 390px 폭에서 전체가 약 0.35배로 축소되어 터치 타깃이 실측 20px 수준이 됩니다. "모바일 조작성" 확인은 현재 데스크톱 기준으로만 유효하며, 실험 노트에 명시하거나 반응형 트랙과 연계가 필요합니다.
- 사소: `zones` 배열이 push만 되고 미사용(죽은 상태), `rotateSelected`에서 id가 한 칸씩 새는 패턴(현재 무해).

### 개선 제안
- 안내 문구를 실제 규칙(Lv.1만 즉시 머지)과 일치시키는 최소 수정을 권장합니다. mistakes 지표가 A/C 비교의 핵심이므로 문구-규칙 불일치는 실험 데이터를 오염시킵니다.
- `update()`가 매 프레임 지표 텍스트를 재생성하므로(`src/merge-prototype.ts:101`) 저사양 모바일 검증 시 값 변경 시에만 갱신하도록 조정할 여지가 있습니다(프로토타입 수준에선 허용 가능).
