# B안 · 모바일 세로 따뜻한 픽셀 Garage

관련 이슈: #177 · 상위 트랙: #166 게임 화면 디자인

## 목적

A안(1120×720 브라우저 크기)과 같은 #114 통합 규칙·데이터를 유지하면서, 출시 목표인 앱인토스 세로 화면에 맞춰 홈 화면 디자인 A안과 동일한 390×810 구조로 재배치한 안입니다. 게임 규칙은 바꾸지 않고 화면 크기·시선 흐름만 비교합니다.

## 화면 구조 (위 → 아래)

1. 작업대 헤더: 공방 이름·경과 시간·머지 횟수
2. 주문 카드: 주문명, 장착 진행(n/4), 부품 4종 목표 칩, 홈 A안 공용 자전거 모델(미장착 부품 반투명)
3. 머지 보드: 6×7, 칸 약 54px — 모양 배치·회전·2-to-1 머지 (A안과 동일 규칙)
4. 안내 메시지: 보드 아래 한 줄
5. 택배 선반: 부품 4종 2×2 버튼 — 주문 → 배송 1.5초 → 개봉 → 배치, 개봉 후 재탭 시 90° 회전

## A안과의 차이

| 항목 | A안 | B안 |
|---|---|---|
| 화면 크기 | 1120×720 가로 | 390×810 세로 (홈 A안 동일) |
| 시선 흐름 | 주문(좌) → 보드(중) → 택배(우) | 주문(상) → 보드(중) → 택배(하) |
| 택배 선반 | 우측 세로 목록 + 회전 미리보기 | 하단 2×2 그리드, 미리보기는 상태 텍스트로 대체 |
| 배치 고스트 | 마우스 호버 미리보기 | 터치 기준이라 제외 (회전 각도 텍스트 표시) |
| 규칙·데이터 | #114 통합 규칙 | 동일 (merge-prototype의 PARTS·ORDERS·팔레트 공유) |

## 검증 절차

1. 홈 A안 데모와 나란히 열어 같은 Garage 팔레트·소재감으로 이어지는지 확인합니다.
2. 택배 주문 → 개봉 → 배치 → 머지 → 자동 장착 → 납품 → 다음 주문 흐름을 완주합니다.
3. 세로 화면에서 세 영역이 스크롤 없이 모두 보이는지, 보드 칸이 터치에 충분한지 확인합니다.

## 한계와 후속

- 브라우저 마우스 기준 데모이므로 실제 터치 판정은 입력 방식 트랙(#33)·모바일 실기기 검증(#4)과 함께 진행합니다.
- Safe Area·노치 대응은 반응형 화면 트랙(#4)의 결과를 따릅니다.
