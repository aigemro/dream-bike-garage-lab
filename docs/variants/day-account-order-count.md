# C안 · 주문 N건 = 하루 일정 + 계정별 진행

- 실험 ID: release-integration / day-session / prototype-c / v1
- 상태: 검토 준비. 하루 주문 수와 체력 수치는 확정하지 않습니다.
- Lab 이슈: [#258](https://github.com/aigemro/dream-bike-garage-lab/issues/258) · 트랙 [#207](https://github.com/aigemro/dream-bike-garage-lab/issues/207) · 규칙 비교 [#210](https://github.com/aigemro/dream-bike-garage-lab/issues/210)
- 메인 관련: [#70](https://github.com/aigemro/dream-bike-garage/issues/70) Day·계정 연결, [#73](https://github.com/aigemro/dream-bike-garage/issues/73) 하트·광고

## 질문
타이머 없이 "오늘 주문 N건"으로 하루를 끝내고 플레이 제한을 알바 체력 하나로 두면, 짧은 세션마다 정산의 성취감이 생기고 이중 제한 문제가 사라지는가?

## 가설
B안(활성 플레이 시간)에 머지 코어 E v3를 연결하면 체력과 Day 시간이 함께 플레이를 막습니다. 체력이 없는데 시간은 흐르거나, 체력이 남았는데 시간이 끝나는 엇갈림이 생깁니다. Good Pizza Great Pizza·Potion Craft처럼 정해진 주문 수로 하루를 끝내면 제한은 체력 하나로 줄고, "한 번 접속 = 하루 일정 + 정산"의 짧은 리듬을 만들 수 있습니다.

## 레퍼런스
| 방식 | 사례 | 하루 종료 | 제한 장치 |
|---|---|---|---|
| 정해진 주문(손님) 수로 하루 종료 | Good Pizza Great Pizza, Potion Craft, Diner Dash | 정해진 손님을 응대하면 정산 | 없음 |
| 게임 속 하루 없음 | Travel Town, Gossip Harbor | 실제 자정에 일일 과제·광고 횟수 초기화 | 에너지 하나 |
| 시계 + 에너지 | Stardew Valley | 잠들기 또는 시계 한계 | 에너지가 하루에 묶여 하루마다 회복 |

조사한 사례 중 실시간 에너지와 플레이 시간 타이머를 함께 쓰는 게임은 없었습니다. C안은 주문 수 방식에 E안의 실시간 체력을 단일 제한으로 붙인 형태입니다.

## 규칙
1. Day를 시작할 때 오늘 주문 수를 고정합니다(Lab 기본 3건, 헤더에서 2·3·5건 전환. 다음에 시작하는 Day부터 적용).
2. 시간 제한은 없습니다. 플레이 화면에 있는 동안의 영업 시간만 기록해 정산에 보여 줍니다.
3. 주문 수를 채운 납품에서 Day가 마감되고, 납품 도장을 잠깐 보여 준 뒤 정산 화면으로 넘어갑니다. 마감 뒤에는 새 입력을 받지 않습니다.
4. 플레이 제한은 E안의 알바 체력(30, 상자당 1, 10분당 1 회복) 하나입니다. 체력이 떨어지면 같은 Day를 다음 접속에 이어서 진행합니다.
5. 정산은 Day마다 한 번만 적용하고, 다음 Day도 같은 주문 수로 준비합니다. 작업대(보드·체력·주문 진행)는 계정별로 저장되어 이어집니다.
6. 같은 계정이라도 B안과 C안의 진행은 따로 저장합니다(계정 프로필은 공유).

## 화면
- 작업대 헤더: DAY 번호, `주문 n/N`, 오늘 수입, 주문 진행 막대(B안의 남은 시간 자리)
- Day 준비: "주문 N건을 납품하면 오늘 일정이 끝나고 정산합니다"
- 정산: "오늘 주문 N건을 모두 납품했습니다", 완료 주문·오늘 수입·영업 시간
- 홈 상단: 상태와 `주문 n/N`

## 평가 기준
- [ ] 한 번 접속해 하루 영업과 정산을 끝낼 수 있는가(3~5분 세션)
- [ ] 체력이 떨어져 Day를 다음에 이어 할 때 답답함이 과하지 않은가
- [ ] 하루 주문 수(2·3·5건)별 체력 소모와 정산 만족감 비교
- [ ] 5일마다 레이스까지의 거리가 진행 목표로 느껴지는가(약 주문 15건 주기)

## 측정 참고
E v3 규칙 시뮬레이션 기준 주문 1건에 상자 약 7개(체력 7)가 듭니다. 체력 30이면 주문 3건 Day를 한 번에 마치고 조금 남습니다. 주문 5건 Day는 대부분 체력 회복을 한 번 기다려야 합니다.

## 실행 방법
Lab → RELEASE INTEGRATION → Day·계정 기반 플레이 세션 → **C안: 주문 N건 = 하루 일정**

계정 로그인 → 프로필 생성 → (헤더에서 주문 수 선택) → Day 시작 → 주문 N건 납품 → 정산 → 다음 Day

## 검증 결과
- 규칙 테스트: 주문 수 고정·활성 시간 기록, 주문 수 도달 마감·중복 집계 방지, 정산 1회·다음 Day 주문 수 유지, 이전 저장 보정. 전체 Vitest와 `npm run build` 통과.
- 브라우저 확인: 주문 2건 Day에서 합성 한 번으로 두 주문이 연속 납품되자 마감 → 납품 도장 → 정산("오늘 주문 2건을 모두 납품했습니다", 2건, +2,400) → DAY 2 준비(주문 2건 유지)까지 진행했고, B안 진행 저장소에는 영향이 없었습니다.
