# 도감형 수집

## 구현 방식
브랜드와 등급별 자전거 목록에서 획득 여부와 전체 진행률을 보여줍니다.

## 확인할 점
빈 슬롯이 다음 수집 목표를 명확하게 만드는지 확인합니다.

## 검토 의견 (2026-08-08)

### 의도 일치
진행률 바, 미획득 카드의 `???` 실루엣, "주문 납품 보상으로 발견" 안내로 "빈 슬롯이 다음 목표를 만드는가"라는 검증 질문에 맞게 구현되었습니다. 획득을 코인 구매로 시뮬레이션한 것도 프로토타입 명시가 있어 수용 가능합니다. 다만 문서의 "**브랜드**와 등급별 목록"은 실제 코드가 카테고리(로드/MTB 등)·등급 축이라 용어가 어긋납니다 — 코드에 맞춰 문서를 갱신하거나 브랜드 축 도입 계획을 명시해야 합니다.
최근 커밋 `0bf496d`(카드-패널 겹침 수정)은 정상 반영을 확인했습니다(2행 카드 하단이 하단 패널과 15px 여유).

### 발견된 문제
- **비활성 상태 미표시**: 발견 버튼이 `active` 플래그 없이 생성되어(`src/collection-prototype.ts:140-143`) 코인이 부족해도 활성 스타일로 보이고 클릭만 조용히 무시됩니다. B/C안은 비활성 처리를 하므로 **세 방안 간 피드백 규칙이 불일치**합니다. 공정 비교를 위해 `this.coins >= 1000` 플래그 추가(1줄) 필요.
- **공통 — 렌더 객체 누수**: `this.children.removeAll()`(`src/collection-prototype.ts:48`)은 객체를 파괴하지 않고 리스트에서만 제거하므로, 클릭마다 전체 재렌더링되는 구조상 텍스트·그래픽·인터랙티브 객체가 누적됩니다. `removeAll(true)`로 파괴해야 합니다. (A/B/C 공통)
- **공통 — 모바일 세로 축소**: 캔버스 960×620 가로 고정 + Scale.FIT이라 390×810 세로에서 약 390×252로 축소되어 버튼이 실측 15px 수준이 됩니다. 겹침은 없으나 터치 타깃 기준 미달 — 실험 노트에 데스크톱 기준 검증임을 명시 권장. (A/B/C 공통)
