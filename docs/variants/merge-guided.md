# 자유 보드 + 주문 가이드 조합형

## 구현 방식
자유 보드의 생성·정리·선행 제작은 유지하고, 현재 주문에 필요한 부품과 목표 레벨을 최소한으로 안내합니다.

## 1차 구현 범위
- A/B와 동일한 6×7 보드·4종 부품·Lv.1~Lv.4 조건
- 부품 종류를 플레이어가 자유롭게 선택
- 주문 3종과 납품 루프
- 다음 목표 텍스트와 관련 셀 강조
- 시간·행동·머지·오입력·빈 칸 수 실시간 표시

## 확인할 점
A안의 공간 관리 자유도를 유지하면서 B안 수준으로 목표 이해도와 주문 완주 템포가 좋아지는지 확인합니다.

## 알려진 제한
1차 구현은 A/B와의 즉시 비교를 위한 기능 검증본입니다. 드래그 이동, 확률형 Lv.2 생성, 소프트 타이머, 품질 보너스와 실제 자전거 조립 연출은 후속 실험에서 다룹니다.

## 검토 의견 (2026-08-08)

### 의도 일치
보드 규칙 A와 공유, 부품 자유 선택, 목표 안내 패널, 지표 표시는 문서대로입니다. 다만 문서와 어긋나는 부분이 세 곳 있습니다.

- **주문 3종 → 실제 2종 순환**: `checkDelivery`가 `(orderIndex + 1) % 2`로 주문 2종만 순환합니다(`src/merge-prototype.ts:596`). 문서의 "주문 3종과 납품 루프"와 불일치.
- **셀 강조 미구현**: "다음 목표 텍스트와 관련 셀 강조" 중 셀 강조는 구현되어 있지 않습니다. `src/main.ts:63`의 "빛나는 목표 표시" 설명도 실제(패널 색 변화)보다 과합니다.
- **보드 크기 A와 상이**: 칸 수(6×7)는 같지만 C의 보드 영역이 A보다 작아 셀 크기가 약 57px vs 74px로 다릅니다. "A안의 조작감을 유지하면서 가이드만 추가"라는 비교 전제가 약해집니다.

### 발견된 문제
- **자동 납품이 선행 제작과 충돌 (가장 중요)**: 목표 레벨에 도달한 부품이 `refreshUi` 시점에 즉시 파괴·납품됩니다(`src/merge-prototype.ts:585-593`). 목표 Lv.1인 부품은 배치하는 순간 사라져 혼란을 주고, 다음 주문을 위해 미리 만든 부품도 현재 주문 목표에 잡히면 강제 납품됩니다. 자유 보드의 핵심 가치인 "선행 제작 유지"와 정면 충돌하므로, 명시적 납품 버튼(또는 목표 패널 클릭 납품)으로 바꾸는 것을 권장합니다.
- **지표 리셋 불일치**: 주문 완료 시 시간(`startedAt`)만 리셋되고 행동/머지/오입력은 세션 누적입니다(`src/merge-prototype.ts:594-606`). 시간은 주문 단위, 행동은 세션 단위라 지표 해석이 어긋납니다. 함께 리셋하거나 누적임을 화면에 표기해야 합니다.
- 방어 코드 권장: 납품으로 파괴된 부품이 `selectedPiece`로 남는 경로를 차단하는 한 줄(`if (this.selectedPiece?.id === match.id) this.selectedPiece = undefined`)을 추가하면 안전합니다(현재 코드 경로에선 재현 어려움 — 추정).

### 개선 제안
- A/C 공정 비교의 핵심은 동일 셀 크기·동일 초기 조건입니다. 보드 크기를 A와 맞추고 가이드 패널을 축소하는 상수 조정을 권장합니다(공통화 리팩터링이 아니므로 Lab 규칙 위반 아님).
- 셀 강조를 구현하거나, 문서에서 해당 항목을 "후속"으로 옮겨 문서-코드를 일치시켜야 비교 결과 해석이 정확해집니다.
