## 질문
E안 작업대의 헷갈리기 쉬운 규칙이 첫 주문 안에 전달되는가?
- 부품을 옮길 수 없음
- 맞닿은 쌍만 합성되고, 결과는 누른 대상 칸에 생김
- 상자는 체력을 쓰고, 부품은 점선 칸에 자동으로 들어옴

## 공통 조건
| 항목 | 내용 |
|---|---|
| 시작 | 열 때마다 첫 영업(시작 보드·첫 주문 어반 로드)부터. LAB 도구 초기화로도 처음부터 다시 시작 |
| 시작 보드 | 프레임 0·1·6, 휠셋 2·3·8 (모두 Lv.1). 구동계·핸들바는 시작과 함께 장착 → 프레임 쌍·휠셋 쌍을 합치면 첫 납품 |
| 측정(LAB 도구 줄) | 첫 납품까지 걸린 시간, 잘못된 탭(빈칸 이동·떨어진 쌍·다른 부품), 힌트 수, 건너뛰기 여부 |
| 공통 | 건너뛰기 가능. 안내가 주문 카드·보드·상자 버튼 중 강조 대상을 가리지 않음 |

## 방안
| 방안 | 내용 |
|---|---|
| **A안 정지 안내 6단계 (메인 현행)** | 주문 확인 → 부품 상자 → 이웃 합성 → 연쇄 보너스 → 장착·납품 → 알바 체력. 스포트라이트와 말풍선으로 설명하고, 안내 중에는 작업대를 누를 수 없음. 끝나면 자유 플레이 |
| **B안 단계 잠금 안내** | 실제 작업대에서 지정한 행동만 허용: 주문 설명 → **프레임 쌍 합성** → **휠셋 쌍 합성** → 납품 설명 → **상자 열기** → 규칙 → 연쇄 보너스. 누를 곳을 스포트라이트와 화살표로 짚고, 다른 곳을 누르면 안내 문구 |
| **C안 맥락 힌트** | 안내 없이 시작. 6초 무입력이면 첫 합성 쌍을 반짝이고, 빈칸 이동 시도·떨어진 같은 부품 선택이 2번 반복되면 이유를 한 줄로 알려 줌. 합칠 쌍이 없고 상자를 연 적이 없으면 상자를 권함. 같은 힌트는 한 번만 |

규칙 모듈: `src/first-shift-tutorial.ts`(단계·허용 행동·실수 분류·힌트 판단, 테스트 `src/first-shift-tutorial.test.ts`) · 안내 레이어: `src/first-shift-tutorial-overlay.ts`

## Lab 확인 기록 (2026-10-09, 개발자 1회 조작 — 사용자 관찰 아님)
| 방안 | 확인 내용 |
|---|---|
| A | 안내 중 보드 탭이 막힘 → 6단계를 넘긴 뒤 프레임·휠셋 합성으로 첫 납품 |
| B | 1단계에서 다른 칸 탭은 막히고 '잘못된 탭' 1 기록 → 프레임 합성 시 휠셋 단계로 → 휠셋 합성 시 납품 단계로 → 상자 단계에서 보드 탭 막힘 → 상자 열기 → 규칙·연쇄 → "안내 끝!" |
| C | 떨어진 같은 프레임 선택 2회 → '떨어진 쌍' 힌트, 빈칸 탭 2회 → '빈칸 이동' 힌트, LAB 도구에 실수 종류별 횟수 표시 |

A안은 안내가 화면을 덮어 막기 때문에, 안내 중에 누른 탭은 '잘못된 탭'으로 세지 않습니다.

## 확인할 것 (사람 플레이, 가능한 인원)
- 첫 납품까지 걸린 시간, 잘못된 탭 수와 종류
- 이해 질문 3개 정답률: 주문 목표는? 어떻게 합성하나? 체력은 언제 쓰이나?
- 건너뛰기 비율, 안내를 다시 보고 싶은지
- 연쇄 보너스(모아서 합성)를 안내 뒤에 시도하는지([#262](https://github.com/aigemro/dream-bike-garage-lab/issues/262): 일부러 노려야만 나옴)

## 메인 적용 시 참고
B·C안은 작업대 입력 처리와 결합됩니다. B안은 단계별 허용 판정(`allowsAction`), C안은 실수 분류(`classifyMiss`)·힌트 판단(`contextualHint`)을 도메인 규칙으로 옮기면 화면과 분리해 테스트할 수 있습니다. 안내 화면은 등급분류 화면에 포함되므로 출시 포함 여부를 함께 판단해야 합니다.
