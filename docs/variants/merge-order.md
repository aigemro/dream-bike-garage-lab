# 주문 목표 중심 머지

## 구현 방식
고객 주문에 필요한 부품과 단계를 먼저 제시하고 해당 목표를 향해 머지합니다.

## 독립 프로토타입 범위
- 자유 보드를 제거하고 커스텀 주문 자체를 플레이 공간으로 사용
- 오른쪽의 프레임·휠셋·구동계·핸들바 버튼으로 Lv.1 부품을 직접 추가
- 같은 종류·같은 레벨 부품 2개가 쌓이면 주문 안에서 자동 머지
- 주문 카드에서 보유 레벨, 목표 레벨, 완성 여부를 즉시 표시
- 완성된 부품은 강조하고 네 부품이 모두 완성된 상태를 유지해 결과 비교

이번 B안은 커스텀 주문을 어떻게 보여주고, 클릭으로 추가된 부품과 완성된 부품을 어떻게 구분할지에 집중합니다. 자유 보드와 주문을 결합하는 방식은 Prototype C에서 비교합니다.

## 확인할 점
보드 없이 주문 자체가 플레이 공간으로 이해되는지, 부품 추가·자동 머지·완성 상태가 한눈에 들어오는지 비교합니다.

## 검토 의견 (2026-08-08)

### 의도 일치
문서 범위 그대로 구현되었습니다. 주문 카드가 플레이 공간이 되고, 버튼으로 Lv.1 추가, 같은 레벨 2개 자동 머지, 보유/목표/완성 표시, 완성 부품 강조와 완성 상태 유지까지 모두 확인했습니다.

### 발견된 문제
- **세 번째 주문 도달 불가**: 주문 텍스트는 `CUSTOMER ORDER n/3`(`src/merge-prototype.ts:614`)이고 세 번째 주문 데이터와 이름 분기까지 존재하지만, 주문 전환이 0↔1 토글이라 세 번째 주문은 죽은 코드입니다. "1/3" 표기는 사용자에게 주문 3개라는 잘못된 기대를 줍니다. 3종을 살리거나 표기를 `n/2`로 맞추는 정리가 필요합니다.
- **보유 부품 칩 5개 초과 미표시**: 칩을 `slice(0, 5)`로 잘라(`src/merge-prototype.ts:633`) Lv.1을 연타하면 실제 보유량과 표시가 어긋납니다. "+n" 표기 등 최소 보완 권장.
- **데모 헤더 오표기**: B안은 보드가 없는데 헤더에 `6×7 · 4 PARTS`가 표시됩니다(`src/main.ts:218`). A/C용 라벨이 B에도 적용된 것으로, 방안별 라벨 분리가 필요합니다.
- 사소: 목표 초과 레벨(예: 목표 Lv.2인데 Lv.3 도달)도 동일하게 완성 처리되어 "과잉 제작"이 지표로 구분되지 않습니다.

### 개선 제안
- 죽은 세 번째 주문 처리(살리기 또는 제거)가 우선입니다. 문서의 "주문 2종 비교" 의도와 코드를 일치시키는 것이 실험 해석에 안전합니다.
