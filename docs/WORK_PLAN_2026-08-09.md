## 남은 작업 (우선순위 순)

1. **부품 수급 A/B/C 비교 데모 구현** — 같은 보드·부품 구성에서 수급 방식만 바꾼 Phaser 데모. A안(즉시 생성)은 현행 머지 프로토타입 로직 재사용 가능. ([#70](https://github.com/aigemro/dream-bike-garage-lab/issues/70)~[#73](https://github.com/aigemro/dream-bike-garage-lab/issues/73))
2. **보드 크기·잠금 칸 검증 데모 구현** — 머지 코어 A안 규칙 고정, 보드 조건만 6×7 / 7×9 / 잠금 해제형으로 전환. 메인 8/13(M0) 보드 크기 결정 지원 목표. ([#74](https://github.com/aigemro/dream-bike-garage-lab/issues/74))
3. **보상·성장 A/B/C 비교 데모 구현** — 같은 주문·납품 흐름에서 보상 규칙만 교체. C안 소프트 타이머가 차별화 지점 후보. ([#20](https://github.com/aigemro/dream-bike-garage-lab/issues/20), [#21](https://github.com/aigemro/dream-bike-garage-lab/issues/21), [#75](https://github.com/aigemro/dream-bike-garage-lab/issues/75))
4. **주문·조립 A/B 데모 구현** — 기존 등록된 준비 중 방안. ([#17](https://github.com/aigemro/dream-bike-garage-lab/issues/17), [#18](https://github.com/aigemro/dream-bike-garage-lab/issues/18))
5. **지도 문서 상태 정리** — [LAB_PROTOTYPE_MAP.md](LAB_PROTOTYPE_MAP.md)의 수집 트랙이 마인드맵·현황표에서 "이슈 준비/준비"로 남아 있으나 실제 허브에서는 A/B/C 모두 체험 가능 상태. 드림 바이크 C안([#60](https://github.com/aigemro/dream-bike-garage-lab/issues/60))도 현황표에 없음. 다음 지도 갱신 때 일괄 정리 필요.

## 진행 원칙 메모

- 데모 구현 시 같은 트랙은 같은 초기 조건(보드·부품·주문)을 유지해 비교 왜곡을 방지합니다.
- 구현 완료와 채택을 구분합니다. 데모가 실행되더라도 비교 전에는 채택하지 않습니다.
- 실험 완료 기준은 메인 이슈에 결과 전달 + 양방향 링크입니다 ([EXPERIMENT_GUIDE.md](EXPERIMENT_GUIDE.md) 참고).
